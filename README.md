**XartIA — рабочее пространство коллектива, где код — общее достояние,
роли выдаются на срок, а вклад виден и проверяем.**

Это не «ещё один таск-трекер». Это попытка собрать в коде социальный
механизм: задачи, проверка результата, репутация (Поток) и казна живут
по правилам Хартии, а не по настроению администратора.

---

## Что здесь происходит

Коллектив берёт задачи, прикладывает результат (PR/коммит), получает
независимую проверку (ОТК) и **Поток** — подтверждённый вклад. Роли —
временные мандаты, которые истекают и ротируются. Деньги — отдельно:
казна с полом 1.00, траты только 3 подписями из 5, Поток нельзя обменять
на власть.

Ядро уже работает: 56 миграций, 36 автоматических проверок в CI,
полный контур «заявка → участник → задача → отчёт → ОТК → Поток»,
казна, Шлюз, Совет, панели, право на пересмотр.

## Кому здесь место

- **Разработчикам** — ядро на Fastify + PostgreSQL + React; нужны руки,
  глаза и аккуратность.
- **Тем, кто думает о социальном устройстве** — Хартию можно и нужно
  оспаривать; в обсуждениях есть место философии, если она превращается
  в проверяемое правило.
- **Новичкам** — здесь **нет слабых и сильных**. Есть люди с разным
  уровнем знаний, и они им делятся. Первая задача должна занимать вечер,
  а не неделю, и рядом будет человек, к которому можно прийти с вопросом.

**Главное правило:** если что-то непонятно — спроси. За вопрос не
расстреливают и не обзывают. Ответим в меру сил, обычно в течение суток.

## Попробовать

### Если вы не программист

1. Прочитайте Хартию: <https://vamhana.github.io/hartia/charter/>.
2. Принесите её вопросы и сомнения в [Discussions](https://github.com/vamhana/xartia/discussions)
   или в [Telegram](https://t.me/hartia_5).
3. Если хотите проверить Хартию на прочность — прогоните её через любого
   ИИ и покажите, где она противоречит себе. Это ценнее, чем согласие.

### Если вы разработчик (5–10 минут)

Нужны: Docker, Node.js 22+, pnpm.

```powershell
git clone https://github.com/vamhana/xartia.git
cd xartia
pnpm install

# инфраструктура: Postgres + PostGIS, Redis, MinIO
docker compose -f docker/docker-compose.yml up -d postgres redis minio

# схема и первый участник (Архитектор)
pnpm db:migrate
pnpm tsx scripts/ensure-architect.ts
pnpm db:migrate

# API :3000, WebSocket :3001, веб :5173
pnpm dev
```

Проверка, что всё живо:

```powershell
pnpm typecheck          # типы API
pnpm typecheck:web      # типы веба
pwsh scripts/ci-local.ps1   # полный локальный прогон: 36 проверок (Windows)
```

Подробнее в [CONTRIBUTING.md](CONTRIBUTING.md). Если стек не встаёт:
[docs/troubleshooting.md](docs/troubleshooting.md).

## Как присоединиться

1. **Познакомиться.** [Discussions](https://github.com/vamhana/xartia/discussions) —
   идеи и Хартия; [Telegram](https://t.me/hartia_5) — быстрые вопросы.
2. **Взять первую задачу.** Ищите метку
   [`good first issue`](https://github.com/vamhana/xartia/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22).
   В каждой задаче написано: что сделать, где смотреть код и как проверить.
3. **Сделать и показать.** Форк → ветка → PR. Если застряли — напишите
   в задаче или в Telegram, поможем.

Правила простые: не обесценивать чужой уровень, не приватизировать роль,
не молчать, если видите проблему. В спорном вопросе действуем по логике
и духу Хартии, а не по букве.

## Стек

- **API**: Fastify 5, TypeScript, PostgreSQL 15 + PostGIS, Redis 7, S3/MinIO
- **Realtime**: WebSocket-каналы (`src/ws`)
- **Web**: React 19, Vite, TanStack Query
- **Инфраструктура**: Docker Compose, k3d + kustomize
- **Проверки**: 36 шагов CI (типы, сборка, миграции на чистой базе, smoke)

## Заметка про инструменты

Для быстрого чтения и правок кода можно использовать
`npx @deepseek-ai/dsh web` — это **платный** инструмент (дают небольшой
стартовый баланс). Это не обязательный путь: всё то же самое делается
бесплатно через Docker и обычный редактор. Упоминаем, потому что с ним
быстрее разобраться в большом репозитории.

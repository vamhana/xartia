# Первый день хартийца

Короткий путь «зашёл → не ушёл». Семь шагов, нормальные вопросы,
куда писать если застрял, и чек-лист для наставника.

Связанные материалы: [Хартия](https://vamhana.github.io/hartia/charter/),
[CONTRIBUTING.md](../CONTRIBUTING.md),
[docs/troubleshooting.md](troubleshooting.md).

---

## Семь шагов

### 1. Прочитать Хартию

Откройте <https://vamhana.github.io/hartia/charter/>. Достаточно частей
про смысл, Поток, ОТК и наставничество. Не нужно заучивать: цель -
понять, *за что* здесь начисляют вклад и *как* принимают работу.

Если формулировка режет глаз, запишите вопрос. Это уже вклад
(см. раздел «Нормальные вопросы» ниже).

### 2. Представиться

Напишите коротко в [Telegram: hartia_5](https://t.me/hartia_5) или в
[GitHub Discussions](https://github.com/vamhana/xartia/discussions):

- как вас зовут (или ник);
- чем хотите помочь (код, документация, проверка Хартии, сценарии);
- сколько времени реально можете уделять в первую неделю.

Шаблон не обязателен. Одного абзаца хватает.

### 3. Выбрать `good first issue`

Откройте список:
[`good first issue`](https://github.com/vamhana/xartia/issues?q=is%3Aissue+is%3Aopen+label%3A%22good+first+issue%22).

Берите задачу, где в описании ясно:

- что сделать;
- в каких файлах;
- как проверить.

Если таких нет, спросите в Telegram: «есть ли задача на первый день?».
Не берите сразу несколько.

### 4. Получить наставника

Напишите в Telegram, что взяли issue `#N`, и попросите наставника.
По Хартии наставника назначает куратор направления; на практике в
открытом репозитории достаточно человека, который:

- ответит на вопрос в тот же день или напомнит, когда сможет;
- посмотрит черновик PR до формального ревью.

Пока наставник не ответил, можно готовить окружение по
[CONTRIBUTING.md](../CONTRIBUTING.md) и
[docs/troubleshooting.md](troubleshooting.md). Не ждите молча больше
суток: напомните о себе один раз.

### 5. Сделать работу

Один узкий PR лучше большого. Перед пушем локально:

```powershell
pnpm typecheck
pnpm typecheck:web
pnpm exec vitest run
```

Если стек не встаёт, сначала troubleshooting, потом Telegram с номером
шага и текстом ошибки.

### 6. Показать результат

Откройте PR по шаблону из CONTRIBUTING:

- ссылка `Fixes #N`;
- что изменилось и как проверить;
- если меняли правило Хартии, ссылка на обсуждение.

Попросите наставника глянуть до или вместе с ревью мейнтейнера.
Правки по ревью - нормальная часть пути, не провал.

### 7. Получить Поток

Поток начисляется за **принятый** результат (приёмка ОТК / merge по
правилам направления), а не за «я открыл PR» и не за часы online.
После приёмки спросите наставника, виден ли вклад в вашей карточке.
Если нет, это баг процесса: его тоже можно оформить issue.

## Нормальные вопросы

Нормально спросить:

- «не понимаю этот абзац Хартии, можно своими словами?»
- «какой файл трогать в issue `#N`?»
- «у меня падает `pnpm db:migrate`, вот лог»
- «мой PR слишком большой? как разрезать?»
- «кто может быть наставником на эту задачу?»

Ненормально только одно: молчать три дня и потом принести сюрприз без
контекста. Вопросы не снижают Поток и не «портят репутацию».

## Если застряли

| Ситуация | Куда |
|---|---|
| Быстрый вопрос по шагу или ошибке запуска | [Telegram: hartia_5](https://t.me/hartia_5) |
| Спор о смысле правила, идея, сценарий | [Discussions](https://github.com/vamhana/xartia/discussions) |
| Баг в коде или в доке | [Issues](https://github.com/vamhana/xartia/issues/new/choose) |
| Стек не поднимается | сначала [troubleshooting](troubleshooting.md), потом Telegram |
| Секрет / уязвимость | **не** в issue - лично в Telegram |

В сообщении укажите: шаг из этого файла, команду, полный текст ошибки.
Скриншот приветствуется.

## Чек-лист наставника

Перед тем как сказать «ты на пути», пройдите список:

- [ ] Человек представился и назвал доступное время
- [ ] Выбрана **одна** задача с меткой `good first issue` (или явно
      согласованная замена)
- [ ] В issue есть комментарий «беру» / ссылка на будущий PR
- [ ] Новичок знает, куда писать при блокере (Telegram / Discussions)
- [ ] Окружение либо поднято, либо зафиксирован конкретный блокер из
      troubleshooting
- [ ] Черновик PR посмотрен до merge: scope узкий, есть способ проверки
- [ ] После приёмки объяснено, откуда берётся Поток и где его видно
- [ ] Договорён follow-up: следующая задача или пауза без чувства вины

Если пункта нет в продукте (нет роли наставника в UI, нет начисления
за ученика), скажите об этом прямо и укажите issue/roadmap. Скрытый
разрыв хуже честного «пока вручную».

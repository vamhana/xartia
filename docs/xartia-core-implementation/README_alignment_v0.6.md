## Основные принятые решения

- Ячейка долговременна; фактический состав существует в версии ростера смены.
- Один план участника на локальный день может содержать блоки нескольких смен.
- Мандат координатора длится 168 часов и начинает действовать после принятия участником.
- Задача имеет стабильную идентичность и immutable TaskRevision; отдельный ImplementationCycle держит дерево исполнения внутри общего плана направления. Один Plan может содержать много циклов.
- Старый package остаётся в границах своего Plan; перенос незавершённой работы выполняется через successor deliverables.
- Родительский результат проходит отдельный ParentOutcomeReview.
- TeamCapability оценивает только конкретную конфигурацию в конкретном ImplementationCycle; старая оценка не переносится.
- Данные без доказуемой исторической привязки остаются legacy_unbound/unresolved.
- Переход — expand–migrate–switch–contract, без dual-write двух источников истины.

## Логика ключевых выборов

- **ImplementationCycle вместо «один Plan = одна задача».** В коде Plan — общий план направления, поэтому уникальная привязка к одной долгосрочной задаче разрушила бы существующую семантику. Цикл получает собственный root package и остаётся внутри того же Plan.
- **RosterVersion — источник состава, TeamConfigurationVersion — снимок оценки.** Это исключает конкурирующие версии одного и того же списка людей.
- **168 часов от принятия мандата.** Это однозначная неделя без зависимости от DST; полномочие не возникает без согласия человека.
- **Непринятый handover остаётся у передающего.** Получение контекста не должно незаметно менять ответственного.
- **Поток урегулируется за локальный день участника.** Это соответствует персональному дневному плану; поздний провал создаёт компенсирующую запись вместо переписывания истории.
- **Неизвестные исторические связи не backfill-ятся догадкой.** Они остаются legacy_unbound/unresolved, потому что ложная точность опаснее явной неполноты.

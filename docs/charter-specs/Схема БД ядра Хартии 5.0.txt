Схема БД ядра Хартии 5.0
Ниже — полная схема. PostgreSQL-стиль. Разбито по доменам. С префиксами, связями, индексами, ключевыми полями и правилами.

0. Общие принципы
Все таблицы имеют id, created_at, updated_at.

Все значимые действия пишутся в audit_log.

Мягкое удаление: deleted_at (никогда не физическое).

Версионирование: version, valid_from, valid_to.

Роли и права — через RBAC + мандаты.

Персональные данные — шифрование (pgcrypto).

Ничего не «навсегда» — у всего есть срок.

29. Ключевые триггеры
Ротация: при mandates.expires_at <= now() — автоматически создать rotations и перевести мандат в «Истёк».

Холодный период: при завершении мандата — создать cooldowns.

Возврат Потоков: ежедневно пересчитывать flow_returns.

Логирование: на INSERT/UPDATE/DELETE ключевых таблиц — запись в audit_log.

Превышение лимитов: при iterations >= 3 — эскалация в Арбитраж.

Просрочка: при deadline <= now() — сигнал в Балансировку.

Информационная блокада: при отсутствии данных Шлюза > 1 часа — автоматическая активация.

Стальной Колокол: при сигнале угрозы > 10% — автоматическая активация.

Семантический дрейф: при игнорировании > 3 часов — эскалация на Форум.

Вне сети доверия: пересмотр через 6 месяцев.

30. Ключевые правила БД
Мягкое удаление. deleted_at вместо DELETE.

Версионирование. Ключевые сущности (блага, стандарты, панели, ядро) — версии.

Шифрование. Персональные данные — pgcrypto.

Партиционирование. audit_log, flow_transactions, access_log — по дате.

Индексы. На FK, status, created_at, external_id.

Ограничения. CHECK на форматы, UNIQUE на external_id.

Триггеры. Логирование, ротация, эскалация.

Репликация. Read-replica для аналитики.

Бэкапы. Ежедневно, с проверкой восстановления.

Изоляция. Шлюз — отдельная схема БД, физически изолированная.
